# Gemini Workspace Context

## Project Overview

This is a modern React frontend web application project built with Vite and TypeScript. It appears to be a Lovable project (AI-generated or AI-assisted codebase). The application implements a landing page structure with various sections like Hero, Services, Testimonials, and Contact.

**Core Technologies:**
*   **Framework:** React 18
*   **Language:** TypeScript
*   **Build Tool:** Vite
*   **Styling:** Tailwind CSS
*   **UI Components:** shadcn/ui (based on Radix UI primitives)
*   **Routing:** React Router (`react-router-dom`)
*   **Data Fetching & State:** React Query (`@tanstack/react-query`)
*   **Animations:** Framer Motion (`framer-motion`) and `tailwindcss-animate`
*   **Forms & Validation:** React Hook Form (`react-hook-form`) + Zod (`zod`)
*   **Icons:** Lucide React (`lucide-react`)

## Building and Running

The project uses `npm` as its package manager.

*   **Install dependencies:**
    ```bash
    npm install
    ```
*   **Start development server:** (Runs Vite with hot-module replacement)
    ```bash
    npm run dev
    ```
*   **Build for production:**
    ```bash
    npm run build
    ```
*   **Preview production build locally:**
    ```bash
    npm run preview
    ```
*   **Run linter:**
    ```bash
    npm run lint
    ```
*   **Run tests:**
    ```bash
    npm run test
    ```
    *(Use `npm run test:watch` to run tests in watch mode)*

## Development Conventions

*   **Directory Structure:**
    *   `src/components/ui/`: Contains reusable, primitive UI components generated by shadcn/ui.
    *   `src/components/landing/`: Contains feature-specific components for the landing page (e.g., `Hero.tsx`, `Footer.tsx`).
    *   `src/pages/`: Contains the main route components (`Index.tsx`, `NotFound.tsx`).
    *   `src/hooks/`: Contains custom React hooks.
    *   `src/lib/`: Contains utility functions (like `utils.ts` often used by shadcn/ui for class merging).
    *   `src/test/`: Contains setup files and test suites.
*   **Styling:** The project relies heavily on Tailwind CSS for utility-first styling. The `tailwind.config.ts` file manages the design system configuration.
*   **UI Components:** The project follows the `shadcn/ui` pattern where components are copied directly into the codebase rather than installed as a single npm dependency. When updating or adding these components, follow standard shadcn/ui practices.
*   **Testing:** Vitest and React Testing Library are configured for unit and component testing.

## Reglas Especiales Actuales (Internacionalización - i18n)
- Cuando se te pida traducir un componente, SIEMPRE extrae los textos a un formato JSON estructurado (es.json y en.json).
- Mantén las llaves de los JSON organizadas por componente (ej. `"hero": { "title": "..." }`).
- Al reescribir el componente de React, importa `useTranslation` de `react-i18next` y usa la función `t()`.
- NUNCA modifiques las clases de Tailwind CSS ni la lógica subyacente al traducir.
- Devuelve solo los bloques de código listos para copiar y pegar.
